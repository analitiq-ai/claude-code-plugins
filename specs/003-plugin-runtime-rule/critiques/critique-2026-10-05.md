## Executive Summary

The problem is real and well-evidenced. Plugins ship `scripts/validation_request.py`, and six
plugin agents grant `Bash`. The scope is tight: a rule only, split from the compliance PR per
Principle VI. Stating the class by mechanism instead of by component list (R3) is the right call.
Two gaps would ship false or incomplete guidance:

1. FR-012 bans only *declared* shell grants. An agent that declares no `tools:` inherits `Bash`,
   and so does a built-in agent type a plugin dispatches.
2. FR-010's escape route ("moves to a tool on the remote MCP server") is wrong for capabilities
   that act on the user's disk. `registry-browser` is the live example.

Both are wording fixes to the spec and the rule body. Neither needs a redesign.
